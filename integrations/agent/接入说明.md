# Character Studio · Agent 接入

0.3.0 的默认入口是 **Skill + 随包程序**。普通用户只发 GitHub 项目链接，说“安装并打开”；Agent 根据包内 INSTALL.md 完成安装与启动。默认流程不进入 MCP 设置页面，不另装 Node，不执行 npm 安装。

Windows 发行包 `character-studio-windows-x64.zip` 自带运行环境。`package:agent` 生成的是供开发者调试的轻量包，不能冒充无需运行环境的最终安装包。

## 普通用户流程

选一位主角 → 预览并确认服装和姿势 → 点击生成。工作台依次生成整批图片。点击「成功记录」打开弹窗查看结果。主角、素材缓存、队列、结果和 Key 在各用户电脑保存。

## Agent 执行

先阅读 INSTALL.md，再读取 skills/character-studio/SKILL.md。固定程序提供 open、doctor、state、wait、result、disconnect、unavailable。使用随包 runtime/node.exe 执行 dist/cli.mjs，不让用户输入命令。

豆包工作桌面端先用 `open --executor keep --no-browser --host doubao` 启动服务，再用内置浏览器打开返回的完整地址。默认让用户先提交，再发送「处理工作台里待生成的图片」，由豆包按技能接手整批。其他宿主可使用已有的 MCP Apps 或本地浏览器面板。内置浏览器打不开时，用 `open --executor keep` 自动打开系统浏览器，豆包须附加 `--host doubao`。

Agent 退出、等待结束或缺少生图工具时，不能宣称保持原生生图连接。回到聊天说“打开人物工作台”可让已加载技能的 Agent 重新启动并连接。客户端无法执行本机程序时应说明限制，不转为长时间 Computer Use 配置尝试。

## 生图与边界

- 当前 Agent：必须实际具备读取参考图、生图、取得真实输出文件或字节的能力。页面提交由真实的等待请求接收；图片生成仍由宿主原生工具执行。
- 本机 Codex：复用已有登录的自动执行器。
- 生图 API：预设 OpenAI、Google Gemini、火山方舟 Seedream，提供自定义兼容协议。用户在弹窗填写 Key，后端完成请求并保存真实图片，不自动切换付费渠道。

API 接入按文档协议实现并使用隔离接口验证，不代表用户账号的权限和余额已被实际测试。豆包客户端的原生生图仍待用户实机验收。

## 开发者可选 MCP 接入

仅在目标宿主已有可验证的原生安装入口时配置。开发包 configure.mjs 可生成 stdio 启动示例；它不是豆包已认证的插件清单，也不是默认用户安装步骤。不要猜测豆包配置目录。
